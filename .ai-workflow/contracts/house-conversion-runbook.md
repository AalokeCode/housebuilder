# House Conversion Runbook — Image References → HouseSpec

Version: 1.1 · 2026-11-02 (paths match the implemented single-app repo)
Audience: **Claude Code agent instances** (orchestrator + workers) converting a property's reference images into a tourable 3D house.
Companion: `.ai-workflow/contracts/3d-house-tour-plan.md` (platform architecture).

> Read this file once, top to bottom, before touching a house. Do not read other `.ai-workflow/` files unless a step below names them.

---

## 0. TL;DR for agents

1. Input lives in `models/houses/<slug>/refs/`. Output is `models/houses/<slug>/house.json` (HouseSpec v1) + `models/houses/<slug>/report.md`.
2. **Look at each image exactly once.** Write what you see into `models/houses/<slug>/work/photo-index.json`. Afterwards work from the index, not the images.
3. Author **rooms as polygons**. Walls are generated by the compiler from room edges — never author walls by hand.
4. Use the **defaults & priors tables** (§4) for anything you can't see. Mark it `"est": true`.
5. Run `pnpm house:validate <slug>` → fix → `pnpm house:preview <slug>` → screenshot photo-match cameras → compare → report.
6. Never invent structural features you have no evidence for. Unknown = leave out + list it under "Open questions" in the report.

---

## 1. Folder convention

```
models/houses/<slug>/
  refs/                 # INPUT — read-only for agents
    01.jpg 02.jpg ...   # listing photos (required)
    plan.(png|pdf)      # floor plan (optional)
    video-notes.md      # human notes from a walkthrough video (optional)
    brief.md            # optional: address, unit type, known sizes (e.g. "1BR, 78 m²")
  work/                 # scratch, agent-owned, committed for traceability
    photo-index.json
    rooms/<roomId>.items.json   # per-room furniture (parallel workers)
  house.json            # OUTPUT — HouseSpec v1 (merged)
  report.md             # OUTPUT — assumptions, confidence, open questions, screenshots
  shots/                # OUTPUT — preview screenshots per photo-match camera
```

`<slug>` = kebab-case, e.g. `dubai-creek-1br-2304`.

## 2. Agent roles & file ownership

Fast path is **1 orchestrator + N room workers**. Small units (≤ 3 rooms) → orchestrator does everything alone; don't spawn.

| Role | Owns (writes) | Reads | Stages |
|---|---|---|---|
| Orchestrator | `photo-index.json`, `house.json` (shell + merge), `report.md` | refs/, this runbook | 1, 2, 3, 4, 6, 7, 8 |
| Room worker (one per furnished room) | `work/rooms/<roomId>.items.json` only | `photo-index.json`, `house.json` (read-only), relevant refs/ images listed for that room | 5 |

Rules:
- A worker **never** edits `house.json` or another room's file. Conflicts are impossible by construction.
- Orchestrator spawns workers only **after** Stage 4 is validated (shell geometry is frozen).
- Worker prompt template (copy exactly, fill `<>`):

```
You are a room worker for house <slug>, room <roomId>.
Read: .ai-workflow/contracts/house-conversion-runbook.md §5, §6, §7 (Stage 5 only).
Read: models/houses/<slug>/house.json (read-only), models/houses/<slug>/work/photo-index.json.
Images for this room: <list of refs/ files>. View each once.
Write ONLY models/houses/<slug>/work/rooms/<roomId>.items.json.
Then run: pnpm house:validate <slug> --room <roomId>. Fix until clean.
Return: item count, placeholders used, open questions (≤ 5 lines).
```

## 3. Coordinate system & units

- Units: **meters**, angles in **degrees**.
- Plan view (top-down): **x → right (east), z → down (south)**. 3D: y up (three.js). Plan z = 3D z.
- Origin `(0, 0)` = top-left corner of the unit's bounding box on the plan. All coordinates ≥ 0.
- Polygon vertices ordered **clockwise as seen on the plan**. Edge `k` = vertex `k` → vertex `k+1` (last wraps to 0).
- Item rotation `rotY`: 0 = item's front faces **+z (south)**; 90 = faces +x (east); 180 = north; 270 = west.
- Round coordinates to **0.05 m**. Rooms must share **identical** vertex coordinates on shared edges (snap!).

## 4. Defaults & scale priors

### 4.1 Defaults (use when not observable — mark `"est": true`)
| Thing | Default |
|---|---|
| Ceiling height (apartment / villa) | 2.70 / 3.00 |
| Exterior wall thickness | 0.25 |
| Interior wall thickness | 0.12 |
| Interior door | 0.90 × 2.10 |
| Main entrance door | 1.00 × 2.20 |
| Floor-to-ceiling glass (balcony) | full height, sill 0 |
| Window sill / height | 0.90 / 1.40 |
| Kitchen counter height / depth | 0.90 / 0.60 |
| Upper cabinets depth / bottom | 0.35 / 1.45 |
| Bathroom (unseen, 1BR) | 2.4 × 1.8 |

### 4.2 Scale priors (measure against these in photos)
| Object | Real size |
|---|---|
| Interior door leaf | 0.80–0.90 w, 2.05–2.10 h |
| Light switch / socket height | 1.10–1.20 / 0.30 |
| Dining chair seat / back | 0.45 / 0.85–0.95 |
| Dining table (4-seat round) | Ø 0.90–1.10, h 0.75 |
| Queen / King bed | 1.60 × 2.00 / 1.80 × 2.00 (UAE/EU); 1.52×2.03 / 1.93×2.03 (US) |
| 3-seat sofa | 2.0–2.4 × 0.9 |
| 55" / 65" TV width | 1.23 / 1.45 |
| Cooker / oven width | 0.60 |
| Floor tile (large format) | 0.60 × 0.60 or 0.60 × 1.20 — count tiles! |
| Balcony railing | 1.10–1.20 h |

Scale procedure: pick ≥ 2 independent priors visible in the same photo; if they disagree by > 15 %, prefer door height, then tile count, then furniture.
If `brief.md` gives total area, scale the whole shell so the sum of room areas is within ±5 % of it (record the factor in the report).

## 5. HouseSpec v1 format

Authoring format, compiled to the platform node graph by `src/domain/compiler.ts` (`HouseCompiler`). Zod schema: `src/domain/house-spec.ts` (source of truth — if this doc and the schema disagree, the schema wins; report the mismatch).

```jsonc
{
  "spec": "housespec/1",
  "slug": "dubai-creek-1br-2304",
  "meta": {
    "title": "1BR — Creek Tower 2304",
    "kind": "apartment",            // apartment | villa | townhouse
    "ceiling": 2.7,
    "sources": ["photos"],          // photos | plan | video
    "areaBrief": null               // m² from brief.md if given
  },

  "rooms": [
    {
      "id": "living",                // kebab-case, unique
      "type": "living",              // living|kitchen|dining|bedroom|bathroom|hall|balcony|storage|other
      "name": "Living / Dining",
      "poly": [[0,0],[6.2,0],[6.2,4.4],[0,4.4]],   // clockwise
      "floor": "floor.porcelain.light-grey",
      "walls": "paint.white.matte",                // default for all edges
      "wallOverrides": { "2": "paint.white.matte" }, // by edge index (optional)
      "ceiling": { "height": 2.7, "material": "paint.white.matte", "features": ["linear-diffuser"] },
      "openTo": ["kitchen"],         // rooms with NO wall between (open plan) — shared edge becomes a floor seam
      "est": true
    }
  ],

  "openings": [
    // Between two rooms (interior). `at` = distance along the shared edge from its start vertex to the opening's near side.
    { "id": "d-bed", "kind": "door", "between": ["hall", "bedroom"], "at": 0.3, "w": 0.9, "h": 2.1, "swing": "in-left", "est": true },
    // Exterior / balcony: room + edge index.
    { "id": "w-living", "kind": "slider", "room": "living", "edge": 0, "at": 1.0, "w": 3.2, "h": 2.7, "sill": 0, "frame": "frame.alu.black" }
    // kinds: door | slider | window | opening (empty doorway) | entrance
  ],

  "fixtures": [
    // Built-ins attached to a wall run: kitchens, wardrobes, vanities.
    { "id": "kitchen-run", "kind": "kitchen", "room": "kitchen", "edge": 3, "from": 0.2, "to": 3.4,
      "base": "cab.matte.greige", "top": "counter.quartz.speckled-beige", "upper": "cab.matte.greige",
      "splash": "tile.speckled-beige", "appliances": [{ "cat": "appliance.cooker.60.steel", "at": 1.6 }] }
  ],

  "items": "work/rooms/*.items.json",   // compiler merges per-room files

  "lights": [
    { "room": "living", "kind": "downlight", "grid": [2, 2] },
    { "room": "living", "kind": "pendant", "cat": "light.pendant.glass-globe-3", "pos": [2.0, 2.2] }
  ],

  "hotspots": [
    { "id": "hs-entry", "room": "hall", "pos": [0.8, 0.6] }
  ],

  "photoCams": [
    // One per reference photo. Used to render a matching screenshot for verification.
    { "photo": "01.jpg", "pos": [0.6, 1.5, 0.4], "lookAt": [5.5, 1.0, 4.0], "fov": 75, "est": true }
  ]
}
```

### 5.1 Per-room items file (`work/rooms/<roomId>.items.json`)
```jsonc
{
  "room": "living",
  "items": [
    // Absolute placement:
    { "cat": "sofa.3seat.channel-grey", "pos": [4.6, 3.6], "rotY": 270, "est": true },
    // Or wall-relative (preferred — compiler snaps to wall surface):
    { "cat": "tv-unit.low.white", "against": { "edge": 1, "at": 1.4 }, "gap": 0.02 },
    // Unknown catalog → placeholder box with real dimensions:
    { "cat": "placeholder.pouf", "size": [0.6, 0.45, 0.6], "pos": [3.2, 3.9], "color": "#e6e1d8", "note": "round boucle pouf" }
  ],
  "decor": [
    { "cat": "art.frame.abstract-blue", "against": { "edge": 0, "at": 1.0 }, "y": 1.6, "size": [1.6, 0.9] },
    { "cat": "rug.rect.grey-marble", "pos": [3.4, 2.8], "rotY": 0, "size": [2.4, 1.7] },
    { "cat": "curtain.sheer.grey", "against": { "edge": 0, "at": 0.8 }, "size": [3.6, 2.7] }
  ]
}
```

### 5.2 Catalog & materials
- Catalog ids: `src/assets/catalog.json` → `"<category>.<variant>"`. Grep it, **don't read it whole**: `grep -i '"sofa' src/assets/catalog.json`.
- No good match → `placeholder.<category>` + `size` + `color` + `note`. List every placeholder in the report (asset team sources them later).
- Materials: catalog id (`paint.*`, `floor.*`, `tile.*`, `cab.*`, `counter.*`, `frame.*`) or inline `{ "color": "#hex", "rough": 0.0-1.0 }`. Sample hex from the photo's lit midtones, not highlights or shadows.

## 6. Procedure (stages & gates)

Each stage ends with a **gate**. Don't move on until it passes.

### Stage 1 — Intake (orchestrator)
1. `ls models/houses/<slug>/refs/`. Read `brief.md` / `video-notes.md` if present.
2. Downscale for token efficiency (images are only read once, but keep them small):
   `mkdir -p models/houses/<slug>/work/small && sips -Z 1280 models/houses/<slug>/refs/*.jpg --out models/houses/<slug>/work/small/`
3. If the source is a **collage** (several photos in one image, like a Pinterest pin), split it first (`sips --cropToHeightWidth` or note crop rects) and treat each panel as its own photo `01a`, `01b`, …
- **Gate:** list of photo ids is final.

### Stage 2 — Photo index (orchestrator, view each image once)
For every photo write an entry to `work/photo-index.json`:
```jsonc
{
  "id": "01a",
  "rooms": ["kitchen", "living", "dining"],
  "camera": { "standingIn": "kitchen", "facing": "S-E", "height": "eye", "lens": "wide ~16-20mm" },
  "visibleWalls": [
    { "room": "living", "desc": "full-height glazing, black alu frame, sliding door to balcony, ~3.2 m" },
    { "room": "kitchen", "desc": "single-run kitchen, oven center, 2 doors to right of run" }
  ],
  "objects": [
    { "what": "round dining table walnut, 4 chairs cream upholstered", "room": "dining", "approxPos": "center-left foreground" },
    { "what": "3-seat channel-tufted grey sofa", "room": "living", "approxPos": "right foreground, back to camera-right wall" }
  ],
  "materials": { "floor": "large-format light grey porcelain 60x120 (#e7e6e3)", "walls": "white matte", "ceiling": "white, recessed downlights, linear AC diffuser" },
  "scaleClues": ["door leaf right of kitchen ~2.1 m → ceiling ≈ 2.7 m", "tiles 4 across dining zone"],
  "adjacency": ["kitchen open to living", "two doors off kitchen → likely bathroom + bedroom/hall"]
}
```
- Cross-reference photos: the same object (e.g. the dining table) in two photos = shared anchor → note it in `adjacency`.
- **Gate:** every photo indexed; every room mentioned in ≥ 1 entry or inferred with reason.

### Stage 3 — Room inventory & topology (orchestrator)
1. Build the list of rooms (seen + inferred). Inferred rooms (e.g. unseen bathroom) get `"est": true` and default sizes.
2. Adjacency graph: which rooms touch, which are open-plan (`openTo`), where doors/glazing are.
3. If `refs/plan.*` exists → **trace the plan instead**: room polygons from the plan, scale from printed dimensions; photos only for materials, furniture, openings check. Set `meta.sources` accordingly.
- **Gate:** written topology in `report.md` §Topology (ASCII sketch allowed).

### Stage 4 — Shell geometry (orchestrator)
1. Size each room from scale priors (§4.2); write `rooms[]` polygons with snapped shared edges.
2. Add `openings[]`, `fixtures[]`, `lights[]`, `hotspots[]` (≥ 1 per room, plus 1 per 4 m of corridor), `photoCams[]` (one per photo).
3. `pnpm house:validate <slug> --shell` → fix all errors (closed polygons, no overlaps, shared edges match, openings fit their edge, fixtures fit their run).
- **Gate:** validate clean. Shell is now **frozen**; later changes to `rooms`/`openings` require re-running Stage 4 gate and notifying workers.

### Stage 5 — Furnishing (room workers in parallel, or orchestrator for small units)
1. Read only your room's photo-index entries; view only that room's photos.
2. Place items with `against` where an item backs onto a wall; `pos` otherwise. Respect clearances: walkways ≥ 0.8 m, door swing clear, bed sides ≥ 0.5 m.
3. Match catalog via grep; placeholders when no match.
4. `pnpm house:validate <slug> --room <roomId>` (checks: items inside room, no overlap > 5 cm, hotspots walkable — not inside furniture or within 0.22 m of a wall/furniture edge).
   **Not checked automatically — verify by eye in the dollhouse view:** door swing clearance, walkway widths (≥ 0.8 m), bed side clearance, wall penetration by items.
- **Gate:** validate clean per room.

### Stage 6 — Merge & full validate (orchestrator)
`pnpm house:validate <slug>` — whole house. Fix or bounce back to the room worker with the exact error.

### Stage 7 — Visual verification (orchestrator, Chrome DevTools MCP)
1. Use the running dev server if one exists (check `lsof -iTCP -sTCP:LISTEN | grep next`), else `pnpm house:preview <slug> --port 3210`. URL: `/preview/<slug>?cam=<photoId>&clean=1` (`clean=1` hides UI so the frame is comparable).
2. Fresh DevTools page (per global rules), `resize_page` to the reference photo's pixel size (e.g. 1000×495). For each photo: navigate to `/preview/<slug>?cam=<id>&clean=1`, wait for the scene-ready signal (`evaluate_script` polling `document.querySelector('[data-tour-ready="true"]')`, ≤ 25 s), `take_screenshot` → `shots/<id>.png`.
3. Compare screenshot vs reference side by side. Checklist per photo:
   - [ ] Wall/glazing positions line up (±10 % of frame)
   - [ ] Major furniture in the right place and facing the right way
   - [ ] Floor/wall/cabinet colors in the same family
   - [ ] Nothing floating, clipping, or outside walls
4. Fix → re-shoot. **Max 3 iterations per photo**; leftover mismatches go to the report.
- **Gate:** every photo has a shot + checklist result.

### Stage 8 — Report (orchestrator)
`report.md` template:
```md
# <title> — conversion report
Sources: photos (n) | plan | video   ·   Scale method: <priors used / area factor>
## Topology
<ascii sketch + adjacency>
## Confidence
| Element | Source | Confidence | Notes |
## Estimated / inferred
- bathroom (unseen) — default 2.4×1.8
## Placeholders (need assets)
- placeholder.pouf 0.6×0.45×0.6 #e6e1d8 — round boucle pouf
## Photo match
| Photo | Shot | Pass/Fail | Mismatch notes |
## Open questions for human
1. ...
```

## 6b. Platform features agents must use

| Feature | How |
|---|---|
| Artwork / patterned textiles / rugs | **Copy exactly from the photo.** Crop into `public/houses/<slug>/*.jpg` (perspective-correct with PIL `Image.QUAD` if shot at an angle; keep only the object — no legs/edges of neighbours) and set the item's `"image": "/houses/<slug>/x.jpg"`. Works for `art.*`, `bed.*` (cushions) and `rug.*`. |
| Voice-over | Top-level `"narration": { "_intro": "...", "<roomId>": "..." }` — 1–3 sentences per room, warm real-estate tone, flag estimated rooms honestly. Validator warns on rooms without a line. Subtitles are generated automatically (line-by-line). |
| Free 3D models | Add to `scripts/fetch-assets.ts` (`polyhaven` · `url` (Smithsonian CC0, Khronos) · `zip` (Kenney / Quaternius CC0 packs) · `sketchfab` (CC0/CC-BY, `SKETCHFAB_TOKEN` inline)), `pnpm assets:fetch <id>` (auto-packs to meshopt GLB), then set `"model": "/models/<id>/<id>.glb"`. Textures: Poly Haven or ambientCG (`source: "ambientcg"`). Procedural builder stays as fallback. Reject models whose colour/style contradicts the photo. |
| Guided tour | `"tour": [hotspot ids]` = stop order (default: first hotspot per room). Give each stop hotspot a `"look": [x, z]` so the camera frames what the narration describes; `"label"` renames a chip. Stops must be walkable (validator). |
| Cover / share | `meta.summary` (≤ 240 chars), `meta.locality`, optional `meta.cta {label, href}` (host listing / enquiry page). |
| Publishing | Leave `meta.status: "draft"`. Only after human approval: `pnpm house:publish <slug> --cover <photoId>` (exports photos + OG, sets published). |
| Photo-match cameras | Solve, don't guess: `python3 scripts/camera/solve-camera.py models/houses/<slug>/work/cam-<id>.json` (6–8 structural point pairs + a bounds box). RMS ≤ 20 px = pass; a single large residual points at a mis-sized element; non-convergence means the layout is wrong → ask for a plan. |
| Window view | Image skybox only (`scripts/skybox/build-skyline.py`), aimed at the main glazing via `SKYLINE_YAW`. |
| Ceiling heights | Set per room; open-plan edges between different heights render a bulkhead automatically. |

## 7. Definition of done
- [ ] `house.json` validates (`pnpm house:validate <slug>` exit 0)
- [ ] Every reference photo has a `photoCams` entry and a screenshot in `shots/`
- [ ] Every non-observed value marked `"est": true`
- [ ] Every placeholder listed in report
- [ ] Every room has a `narration` line; every guided stop has a `look`
- [ ] Patterned surfaces (art, rugs, cushions) use photo crops, not procedural patterns
- [ ] `report.md` complete with open questions
- [ ] No files written outside `models/houses/<slug>/` and `public/houses/<slug>/` (plus catalog / fetch-assets for new models — mention in report)
- [ ] Status left as `draft` unless the human approved publishing

## 8. Efficiency rules
- View each reference image **once** (Stage 2). After that, use `photo-index.json`. Workers view only their room's images.
- Never `Read` `catalog.json` whole — grep.
- Don't spawn workers for ≤ 3 furnished rooms; overhead > gain.
- Don't re-validate the whole house after each item — use `--room`.
- Prefer `against` placement over absolute math.
- Keep reports terse: tables, no prose.

## 9. Escalation (stop and ask the human)
- Photos contradict each other about structure (e.g. glazing on two different walls of the same room).
- Area from brief and photo estimate differ by > 20 %.
- Can't tell if a space is a room or open-plan zone and it changes wall count.
- Validator error you can't resolve in 3 attempts — report exact error text.

## 10. Worked example (from sample collage, 3 panels)

Photo index (abridged):
- `01a` kitchen + living + dining, camera in kitchen corner facing S-E. Single-run kitchen with 60 cm cooker; 2 interior doors right of the run; full-height black-frame glazing with slider to balcony; channel-tufted grey sofa, round walnut table + 4 cream chairs, TV on low white unit, round glass coffee tables.
- `01b` bedroom, camera facing E. Queen bed (grey upholstered headboard) against N wall; walnut nightstands; floor-to-ceiling slider to balcony on E wall; blue abstract art 1.6 m wide above bed.
- `01c` living/dining from opposite side (balcony end), facing W. Confirms same table + sofa → same room as `01a`; low walnut sideboard on W wall.

Topology:
```
 ┌──────────────┬──────────┐
 │ kitchen │ hall│ bedroom  │
 │  (open) ├─d───┤          │
 ├─────────┘bath │          │
 │ living/dining └──────────┤
 │                     ▒▒▒▒▒│ ← glazing (both rooms)
 └──────────── balcony ─────┘
```
Rooms: `kitchen` (openTo living), `living`, `hall`, `bathroom` (est), `bedroom`, `balcony`.
Scale: door 2.1 m → ceiling ≈ 2.7 m; sofa ≈ 2.2 m; table Ø ≈ 1.0 m; living depth ≈ 6.5 tile-widths of 0.6 → ~4 m.
